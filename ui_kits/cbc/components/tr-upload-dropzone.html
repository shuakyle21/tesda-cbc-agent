Why rejection is inline and not a toast

The check happens inside the POST, so the answer arrives while the trainer is still looking at the dropzone. Their next action — pick a different file — is one click from where their eyes already are. A toast puts the explanation in a corner, on a timer, away from the control that caused it. The file is not retained on rejection.

Companion — budget rejection

A different failure at a different moment: this one fires on the generate step, before a job exists. It is not a progress screen for a job that instantly died.
