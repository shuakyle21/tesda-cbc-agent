Re-run generation?

This starts a completely new run — all 26 documents are regenerated, including the 24 that succeeded. There is no way to retry just the failed sections.

Why the confirmation is not boilerplate

Re-running burns the full free-tier call budget again (~26 LLM calls minimum) to recover two documents, and it produces a second complete set of 26 rows that the results view then has to disambiguate. The trainer should know that before clicking, not after.

The anti-pattern

Below is what a generator will build by default, and it must not exist. There is no per-section retry API — only whole-job re-generation. A per-row button could only ever restart all 26, so its label is a lie no matter what it says.
